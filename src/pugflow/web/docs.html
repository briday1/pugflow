Pugflow

Complete offline reference for building, styling, editing, and exporting source-first diagrams.

Getting started

A project needs one Pug file and may have one companion CSS file. Pug describes structure and local overrides; CSS holds reusable node, line, and annotation types. The smallest diagram is:

#canvas
  graph
    .node
      .id start
      .label Start

Indentation defines ownership. Use two spaces consistently. Blank lines and lines beginning with // are ignored. Save Pug and CSS to keep the project editable; SVG and PNG are export formats.

Canvas and graphs

#canvas is the single document root. It holds canvas defaults and one or more graph blocks. A graph represents one connected flow and has one root node. Sibling graphs are disconnected; a graph nested inside another graph is visually contained by it.

#canvas
  .background #ffffff
  graph
    .id main
    .label Main process
    .node
      .id root
      .label Root
  graph
    .id separate
    .offset (0, 40)
    .node
      .label Independent graph

Graphs support .id, .label, .offset, .fill, .color, .outline, .outline-style, .outline-width, .padding, and .hidden. Frames are transparent by default.

Nodes

A node may use the built-in .node type or any reusable @node type. Keep identity, label, layout, and appearance fields together beneath it.

.node
  .id service
  .label
    | Service name
    | Multiline description
  .shape rounded
  .width 220
  .height auto
  .fill #ffffff
  .color #111827
  .outline #94a3b8
  .outline-style dashed
  .outline-width 2
  .align left

Directly nesting multiple nodes under a node creates a one-step fanout. Use a flow for a sequence so long pipelines do not require progressively deeper indentation.

Flows

A flow starts at the node containing it and connects its sibling node declarations in sequence. Its first node is placed from the parent’s rendered position, including manual offsets.

.node
  .id start
  .label Start
  .flow
    .direction right
    .ports shared
    .node
      .id validate
      .label Validate
    .node
      .id publish
      .label Publish

Directions are right, left, up, and down. Ports are shared (the default) or distributed. Multiple flows from one node are an explicit fanout, including multiple flows in the same direction.

Merges

A merge is a graph-level relationship. Select two or more existing source IDs and define a new target node.

.merge
  .direction right
  .ports shared
  .source
    .ref api
    .line
      .label live
  .source
    .ref cache
  .node
    .id result
    .label Combined result

The compact form .from api cache may replace explicit source blocks when individual incoming lines need no overrides. Source IDs must already be defined.

Explicit connections

Use .connect when both endpoint nodes already exist, including cross-graph and feedback connections.

.connect
  .from archived
  .from-direction up
  .to active
  .to-direction left
  .ports shared
  .feedback_line
    .label feedback

.from-direction controls the side used to leave the source; .to-direction independently controls the side used to enter the target.

Reusable CSS

Reusable definitions may be written above #canvas in Pug or in the optional CSS tab. CSS uses Pugflow at-rules rather than browser selectors:

@node card {
  shape: rounded;
  fill: #ffffff;
  outline: #94a3b8;
  shadow-color: #000000;
}

@line warning {
  color: #dc2626;
  stroke-style: dashed;
  arrow-style: both;
}

@annotation note {
  color: #2563eb;
  font-style: italic;
}

Use them as .card in place of .node, or as .warning/.note decorators. Local fields beneath an item override its reusable type. Names must be unique across all three definition kinds.

Text and annotations

Nodes, annotations, and connection labels support font-family, font-size, font-weight, font-style, and text-decoration. Nodes additionally support .align.

.node
  .label Important
  .font-size 20
  .font-weight bold
  .font-style italic
  .text-decoration underline
  .annotation
    .above
      .font-size 13
      .color #2563eb
      | Annotation above
    .below Annotation below

Inline $...$ supports a portable TeX-like subset: Greek letters, common operators, superscripts/subscripts, \sqrt{...}, and \frac{...}{...}.

Images and shadows

.node
  .label Profile
  .image photos/profile.png
  .image-width 96
  .image-height 96
  .image-fit contain
  .image-opacity 1
  .image-padding 8
  .shadow-color #000000
  .shadow-offset-x 4
  .shadow-offset-y 5
  .shadow-blur 8
  .shadow-opacity 0.3

The node grows to contain the complete image plus padding. Image fit accepts contain, cover, or fill. Drag the image or its resize handles on the canvas to write image geometry and .image-offset.

Hiding items

Add .hidden to a node, annotation, line, or graph. Hidden nodes remain in layout so before/after versions retain exact placement; their annotations and every touching connection are also hidden.

Canvas editing

  • Click a node, label, annotation, connector, connection label, or graph to select it and jump to its source.
  • Ctrl-click (Cmd-click on macOS) toggles multi-selection.
  • Drag nodes, text, images, and graphs; hold Shift to constrain node/text movement to one axis.
  • The origin ghost shows the previous position while dragging.
  • Use node/line types first, then local inspector values as overrides.
  • Align or distribute multiple selected nodes or graphs from the inspector.
  • Clean up straightens small connector jogs and writes corrected offsets.
  • Undo/Redo and Ctrl+Z/Ctrl+Y cover canvas source edits.
  • Zoom affects preview only; Fit frames the drawing. Exports use diagram bounds.
  • + New contains Graph, Node, Flow, and Merge creation.
  • Copy writes a 2× high-DPI PNG to the clipboard. Save opens format and PNG-resolution options for PNG or SVG export.

Source editor

The editor provides line numbers, current-line highlighting, syntax color, color pickers beside hex values, completions with Ctrl+Space, Tab/Shift+Tab indentation, and click-to-source navigation. Vim mode is off by default and supports Normal, Insert, and Visual modes, a block cursor, movement/edit/yank/paste/marks, >/< indentation, and Escape/Ctrl+[ /Ctrl+C to return to Normal mode.

Pug and CSS files

Open Pug/CSS… accepts a Pug file alone or a Pug and CSS together. The CSS file is optional unless custom types are referenced. Each editor tab shows its actual filename. Save Pug + CSS writes the pair together when supported, with a download fallback. Pugflow intentionally starts blank or with --demo; it does not restore browser state.

Command line

pugflow                         # blank GUI
pugflow --demo                  # GUI with feature tour
pugflow --vim                   # GUI with Vim enabled
pugflow --gui diagram.pug --css diagram.css
pugflow diagram.pug
pugflow diagram.pug --css styles.css --output diagram.png --scale 2
pugflow --no-browser --host 127.0.0.1 --port 4173

Direct rendering uses an installed Edge, Chrome, or Chromium browser. Set PUGFLOW_BROWSER if automatic discovery cannot find it.
